# الأمان (SECURITY.md)

يراعي التطبيق أفضل الممارسات الأمنية للبيئة التي يعمل فيها (تطبيقات الواجهة الأمامية - SPA).

## 1. حماية مفاتيح API (API Keys)
- يتم استخدام المتغيرات البيئية (`.env`) لتخزين المفاتيح الحساسة.
- بما أن المشروع يعتمد كلياً على الواجهة الأمامية، يجب ملاحظة أن أي مفتاح API يُقدم للمتصفح (مثل مفتاح Supabase Anon أو Gemini API) سيكون مرئياً للمستخدم المتقدم.
- **توصيات**:
  - بالنسبة لـ **Supabase**، استخدم (Row Level Security - RLS) بقوة لحماية قاعدة البيانات بحيث لا يستطيع المستخدمون الوصول إلا لبياناتهم الخاصة.
  - بالنسبة لـ **Gemini API**، يُفضل في بيئة الإنتاج الحقيقية إنشاء خادم وسيط (Proxy Server) يخفي مفتاح Gemini ولا يكشفه للواجهة الأمامية لمنع إساءة الاستخدام.

## 2. الحماية من ثغرات XSS
- تعتمد الواجهة على React، الذي يقوم تلقائياً بتهريب السلاسل النصية (Escaping) للحماية من حقن スكربتات برمجية (XSS).
- تجنب تماماً استخدام `dangerouslySetInnerHTML` إلا عند الضرورة القصوى وبعد تعقيم البيانات الواردة.

## 3. حماية البيانات المحلية
- يتم تخزين معلومات التقدم والعلامات في IndexedDB.
- يُنصح بعدم تخزين أي معلومات شخصية أو حساسة جداً بشكل غير مشفر محلياً. البيانات الحالية في التطبيق (آيات وملاحظات عامة) لا تشكل خطراً أمنياً بالغاً.

## 4. الاتصال
- جميع الاتصالات بين التطبيق وخوادم Supabase تتم عبر بروتوكول HTTPS المشفر.
