# دليل التحويل الشامل لمشروع "أنيس القلوب" إلى تطبيق APK احترافي (Offline-First)

هذا الدليل يهدف إلى توجيهك (أو توجيه وكيل الذكاء الاصطناعي الخاص بك) لتحويل هذا المشروع من مجرد تطبيق ويب إلى تطبيق أندرويد/iOS متكامل يعمل بكفاءة عالية جداً وبدون الحاجة الدائمة للإنترنت.

---

## أولاً: المعمارية الهندسية المتطورة (Architecture)

للانتقال بالتطبيق إلى المستوى الاحترافي، نعتمد معمارية **Offline-First** القائمة على **SQLite**.

### 1. كيف تم تصميم هذه المعمارية؟
تم تصميم النظام ليعمل بشكل مستقل عن الخوادم الخارجية. بدلاً من طلب البيانات في كل مرة عبر الإنترنت، يتم دمج قاعدة بيانات SQLite محملة مسبقاً داخل ملف الـ APK.

### 2. لماذا اخترنا هذه المعمارية؟
- **السرعة**: جلب الآيات والبحث يتم في أجزاء من الثانية.
- **الاستقلالية**: المصحف يعمل بالكامل في "وضع الطائرة".
- **الموثوقية**: التطبيق لا يتوقف إذا تعطلت خدمات API الخارجية.

### 3. مخطط تدفق البيانات (Data Flow):
1. **فتح التطبيق** -> قراءة آخر موضع قراءة من SQLite.
2. **عرض السورة** -> جلب الآيات من SQLite (فوري).
3. **التشغيل الصوتي** -> فحص الذاكرة المحلية؛ إذا لم يوجد الملف، يتم تحميله من الإنترنت وحفظه (Caching).
4. **المزامنة** -> عند توفر الإنترنت، يتم رفع الملاحظات والعلامات إلى **Supabase**.

---

## ثانياً: قاعدة البيانات (المصدر الرئيسي للبيانات)

### 1. قاعدة البيانات المحلية (SQLite):
هي المصدر الرئيسي لكل النص القرآني والتفاسير. 
**الجداول المقترحة:**
- `Surahs`: معلومات السور (العدد، النوع، الترتيب).
- `Ayahs`: نص الآيات بالرسم العثماني، أرقام الصفحات، الأجزاء.
- `PageIndex`: فهارس الصفحات للرؤية البصرية.
- `Tafsir`: نصوص التفاسير المرتبطة بكل آية.
- `UserSync`: العلامات المرجعية والملاحظات (قبل مزامنتها سحابياً).

### 2. القاعدة السحابية (Supabase):
تُستخدم فقط لـ:
- حسابات المستخدمين (Authentication).
- النسخ الاحتياطي للمزامنة بين الأجهزة المختلفة.

---

## ثالثاً: المحتوى القرآني والتفاسير

- **مصدر النص**: يتم الاعتماد على **Quran.com API** و **Tanzil.net** للحصول على أدق النسخ بالرسم العثماني.
- **التفسير**: يتم جلب تفاسير (ابن كثير، السعدي، الجلالين) وربطها برقم الآية الفريد (Ayah Key).
- **التحقق**: يتم التحقق من سلامة البيانات برمجياً عبر مطابقة عدد الآيات والكلمات مع المصادر الرسمية الموثقة.

---

## رابعاً: شرح المكونات (Components & Services)

1. **QuranReader**: المكون المسؤول عن العرض البصري لصفحات المصحف (SVG أو Canvas).
2. **QuranAudioPlayer**: مشغل صوتي ذكي يدعم التكرار (للتحفيظ) والتخزين المؤقت للملفات.
3. **QuranDataService**: الخدمة التي تدير جلب البيانات؛ سيتم تعديلها لتعطي الأولوية لـ SQLite Native Plugin في الجوال.
4. **audioCacheService**: نظام إدارة الملفات الصوتية على ذاكرة الهاتف لضمان عملها بدون إنترنت.

## خامساً: خطة تنفيذ التحويل إلى APK (للمطور أو الوكيل)

عند فتح المشروع في **VS Code**، اتبع هذه الخطوات بدقة:

### 1. تهيئة Capacitor:
```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init "Anis Al-Qulub" "com.anis.app"
npx cap add android
```

### 2. دمج SQLite:
1. قم بإنشاء ملف `quran.db` يحتوي على كل البيانات (يمكنك استخدام سكريبت لتحويل JSON الحالي إلى SQL).
2. ضع الملف في مجلد `android/app/src/main/assets/`.
3. استخدم إضافة `@capacitor-community/sqlite` للتواصل مع القاعدة.

### 3. تحديث الخدمات:
قم بتعديل `src/quran-platform/services/QuranDataService.ts` ليستخدم استعلامات SQL بدلاً من `fetch` عندما يكون التطبيق يعمل على الهاتف:
```typescript
if (Capacitor.isNativePlatform()) {
  // Query SQLite
} else {
  // Fetch from API
}
```

## سادساً: نصائح للتطوير المستقبلي (الوضع الكامل بدون إنترنت)

لتحقيق "وضع الأوفلاين الكامل" باحترافية:
1. **تنزيل السور**: أضف خياراً للمستخدم "تحميل السورة كاملاً" ليتم حفظ جميع ملفات الـ mp3 الخاصة بها في مجلد التطبيق.
2. **البحث المحلي**: استخدم ميزة **FTS5** في SQLite لتمكين البحث الفوري في النص القرآني بدون إنترنت.
3. **الخطوط المدمجة**: قم بتضمين خطوط الرسم العثماني (مثل Amiri أو خطوط مجمع الملك فهد) داخل ملفات الـ APK لضمان ظهور النص بشكل صحيح على كافة الأجهزة.
